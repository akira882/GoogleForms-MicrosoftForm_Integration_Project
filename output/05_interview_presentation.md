## Slide 1: 課題の本質

### Microsoft Forms API未対応による統合困難

**問題の背景:**
- Client: Google Formsでデータ収集（既存運用）
- Clientグループ新規傘下企業: Microsoft Formsでデータ収集
- **技術的制約:** Microsoft Forms Graph APIが未GA（2026年2月時点）

**証拠:**
- Microsoft Graph API v1.0 / Beta版ともにForms APIなし
- 公式ドキュメントにも記載なし
- 唯一の方法: Power Automate経由のWebhook連携

**年間M&A複数件のClientグループで発生する問題:**
- 手動データ統合: 週12時間 × 10名 = 週120時間（Forrester調査根拠）
- M&A後の統合: 従来6〜12ヶ月、コスト500〜1,000万円/社
- データ品質問題: 年間5,500万円のコスト（Gartner換算）

## Slide 2: 提案するソリューション概要

### 3フェーズアーキテクチャ図

```
Phase 1（1ヶ月）: Make.com + Power Automate ハイブリッド
  ↓ クイックウィン - ROI回収期間11ヶ月
  
Phase 2（3〜6ヶ月）: BigQuery + Looker Studio分析基盤
  ↓ データドリブン経営の実現
  
Phase 3（6〜12ヶ月）: Claude API自動正規化
  ↓ AI活用によるグループ標準化
```

**技術スタック:**
- Make.com（iPaaS）: $10〜$25/月
- BigQuery: 無料枠内（月間$0〜$30）
- Claude API: $50〜$80/月（Client AIブースト支援金活用）
- Clientトラスト・ログイン SSO連携（セキュリティ強化）

**特徴:**
- ツールを統一せずにデータだけ統合（柔軟性）
- ノーコード/ローコード中心（非エンジニアも運用可能）
- 段階的実装でリスク分散

## Slide 6: リスクと対策（想定反論への回答）

### 想定される質問と回答

**Q1: Power Automateに依存するのはリスクでは？**

**A1:** フォールバック設計を準備済み
- Zapierへの切り替え（48時間以内）
- 手動エクスポート + 自動インポート（1週間以内）
- Power Automateは Microsoft主要製品のため、突然の終了リスクは極めて低い

---

**Q2: Make.comは信頼できるサービスか？**

**A2:** 実績あるiPaaS
- 2016年創業、80万ユーザー
- Fortune 500企業の20%が使用
- SOC2 Type II、GDPR、ISO 27001準拠
- 月間稼働率99.9%以上

---

**Q3: BigQueryのコストが高額になる懸念は？**

**A3:** 実質無料枠内で運用可能
- 月間5万レスポンス想定 → 月間250MB
- BigQuery無料枠: 月間1TBクエリ、10GBストレージ
- 実績として月額$0〜$30程度
- パーティション設計により、クエリコストを最小化

---

**Q4: Claude APIの精度や個人情報漏洩の懸念は？**

**A4:** 匿名化設計と人間レビューフロー
- Claude APIに送信する前に必ず個人情報を匿名化（メールアドレスはSHA-256ハッシュ化、氏名は仮名化）
- AIによる自動マッピングは人間がレビュー
- 精度目標90%以上
- Anthropic社（Claude開発元）はSOC2 Type II準拠

---

**Q5: なぜ既存のATS（採用管理システム）では不十分なのか？**

**A5:** Clientグループの特殊性
- Clientグループ各社が異なるATSを使用（統合困難）
- フォームはATS以外の用途（社内アンケート、入社手続き等）でも使用
- M&A後にATSを統一するには2〜3年かかる（LINEヤフー事例）
- **この提案:** ATSを統一せずにデータだけ統合する柔軟なアプローチ
